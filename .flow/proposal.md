# 方案设计：面向运营人员的「本地数据不进 LLM」自然语言 AI 清洗代码生成器

## 1. 业务背景与问题定义

数据清洗工作台中预置的规则与卡片（去除空格、提取手机号、格式化日期等）只能覆盖常规规则化场景，无法穷举真实业务的长尾脏数据（例如“2026年3月1日-8月1日”拆分为起止日期、从“男内搭(汤锦东)”中分离负责人、复合条件计算等）。
非技术运营人员无法编写 Python/GREL 或复杂正则。同时，企业级数据合规与隐私安全**严禁将大批量明细业务数据上传至云端 LLM**。

## 2. 核心架构与设计原则（三层职责划分）

1. **LLM 推进流程（执行权）**：
   - LLM 只负责根据用户的自然语言需求 + 列名元数据（最多 1~2 行极简脱敏样本），生成可本地执行的确定性 Python/Polars 清洗函数。
   - **底线红线**：明细数据绝对不发给 LLM，全量数据处理 100% 在本地完成。
2. **产品 Harness 承担围栏约束（约束权）**：
   - **沙箱安全**：限制 Python 脚本只能以纯函数形式处理传入的 Polars DataFrame，禁止任意外部网络通信与文件破坏操作；超时熔断机制；
   - **即时 Diff 预览**：执行前先在本地抽取前 10 行执行预览，生成清晰直观的前后对比；
   - **版本回溯**：清洗后生成不可变新版本（v1 -> v2），支持随时一键撤销与历史恢复。
3. **人类负责决策（决策权）**：
   - 运营人员只用自然语言提诉求；
   - 运营人员只看 Diff 对比效果做审批确认；
   - 一键将满意的 AI 清洗固化为命名算子（卡片），未来同类表格可永久一键复用与管道自动化。

## 3. 拟交付的关键模块

- **后端 (`studio-api` & `pybridge`)**：
  1. `POST /api/datasets/:id/ai/generate-cleaning`：接收用户自然语言需求与目标列，调用 LLM 生成纯函数形式的 Python 清洗代码；
  2. `POST /api/datasets/:id/ai/preview-cleaning`：在沙箱内对前 10 行预览试跑，返回变更前后对比明细；
  3. `POST /api/datasets/:id/ai/apply-cleaning`：将代码作用于数据集全量，在 OpenRefine / Polars 中落盘并生成版本与清洗成果单，同时将算子保存到 recipe 历史中。
- **前端 (`studio-web`)**：
  1. 清洗工作台顶部常驻「✨ AI 对话清洗助手」浮窗/输入条；
  2. 针对复杂业务清洗卡片提供「前后对比浮层（Diff Modal）」；
  3. 确认后自动收录为「我的清洗卡片」，支持后续一键调用。
