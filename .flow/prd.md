# PRD: 面向非技术运营人员的数据清洗工作台体验重构

## Problem Statement

非技术运营人员在日常工作中频繁面对各类混乱的业务表格（如销售流水、活动报名表、合作方名册）。现有的数据清洗平台虽然底层能力强大，但整体交互与表达高度技术化：
1. **启动繁琐**：依赖终端执行 `npm`、`uv`、`setup` 命令，缺乏 macOS 桌面开箱即用的双击入口；
2. **认知门槛高**：清洗功能以 GREL 脚本手写、正则替换、算法聚类（Levenshtein/ngram）为主，无编程基础的运营完全无法下手；
3. **缺乏确定性感**：操作前无法直观看到“改动前 vs 改动后”的数据对比，误操作时担心损坏原数据；
4. **无法闭环交付**：没有将清洗流程沉淀为一键复用模板的轻量入口，洗完后缺少向业务主管汇报清洗成果的直观总结凭据。

---

## Solution

将数据清洗平台由“工程师测试台”彻底转型为“非技术运营的无门槛桌面工作台”：
1. **隐形化基础设施**：提供 `启动清洗工作台.command`，双击启动并自动拉起浏览器，实现单实例复用与孤儿进程清扫；
2. **大白话业务卡片库**：将高频数据问题固化为一键点选的“业务清洗卡片”（去空格、手机号11位规范、统一日期YYYY-MM-DD、金额转数值、智能同名找错合并、删空行），手写 GREL 退居高级折叠项；
3. **红绿高亮实时预览与安全后悔药**：任何动作点击前提供“前5~10行红绿前后对比”；历史记录采用大白话流水账，单步支持一键撤销，原始数据永远不可变安全；
4. **一键模板与一页纸成果汇报单**：支持一键将当前步骤定版为“我的日常清洗方案”，下次拖表一键跑完；清洗完成提供可视化“清洗体检报告”，方便汇报交差。

## User Stories

1. **US1（桌面双击即用）**：作为运营同学，我希望双击根目录的 `启动清洗工作台.command` 就能直接在浏览器中打开工作台，无需敲击任何终端命令。
2. **US2（文本一键修剪）**：作为运营同学，选中一列带有空格的文字后，我希望点击“去除首尾空格”或“清理全角空格”卡片，就能直接把多余空格删掉。
3. **US3（手机号标准归一）**：作为运营同学，面对混有 `+86`、空格、破折号的手机号列，我希望点击“手机号规范化”卡片，一键提取规范的 11 位数字。
4. **US4（日期格式统一）**：作为运营同学，面对 `2026/9/1`、`2026.09.01`、`2026-9-1` 混杂的日期列，我希望点击“统一为 YYYY-MM-DD”卡片，一键标准化日期。
5. **US5（金额去符号转数字）**：作为运营同学，面对带有 `￥`、`$` 或千分位逗号的金额列，我希望点击“金额转纯数值”卡片，使其可以在 Excel 中直接计算求和。
6. **US6（智能找错别字与同名合并）**：作为运营同学，面对“腾讯计算机”、“腾讯科技”等同一个主体的不同写法，我希望点击“智能找同名合并”，系统自动把相似词挑出来并推荐标准名称，我勾选确认后一键替换。
7. **US7（空值与空行清理）**：作为运营同学，我希望点击“删除全空行”或“空值填充”，快速去除无用数据或填充默认值。
8. **US8（红绿高亮前后预览）**：作为运营同学，在点击应用任何卡片前，我希望在界面上清楚看到前几行的变动对比（原本的红色划掉，变绿的新内容），确认无误再执行。
9. **US9（单步人话后悔药）**：作为运营同学，当我误操作改错数据时，可以在操作历史里看到“10:15 统一手机号格式”，并点击“撤销此步”瞬间复原，不用担心搞坏原表。
10. **US10（保存为我的日常方案）**：作为每周都要处理固定报表的运营，我希望把今天洗好的 5 个步骤保存为“周一销售表清洗”，下周一直接套用。
11. **US11（一页纸清洗体检单）**：作为运营同学，清洗完导出后，我希望看到一份“本次修复 352 个错误手机号、清理 18 行空行、预估节省手工整理 1.5 小时”的成果单，支持复制文本或截图向上级交差。
12. **US12（高级模式折叠兜底）**：作为有进阶需求的工程师或熟练分析师，我依然可以在折叠区展开“自定义 GREL 表达式”进行复杂逻辑编写。

## Implementation Decisions

1. **桌面启动器实现**：
   - 根目录下创建 `启动清洗工作台.command`（赋予 `chmod +x`），检测 Node、Python、环境端口占用情况；
   - 自动检测并启动 Fastify API，自动在默认浏览器中打开 `http://127.0.0.1:8787`；退出或关闭终端时做孤儿进程回收。
2. **清洗动作库（Action Library）映射层**：
   - 在前端创建结构化的业务卡片预置模板定义，将其映射为成熟、安全的 OpenRefine GREL 表达式与核心操作类型：
     - 去除首尾空格：`value.trim()`
     - 手机号规范化：`value.replace(/[^0-9]/, '').substring(...)` 或智能提取 11 位
     - 日期标准化：转换为 ISO/标准日期串
     - 金额转纯数字：`value.replace(/[￥$,]/, '').toNumber()`
     - 全空行过滤与清理
   - 聚类功能重构为“智能同名找错合并”业务组件，对齐小白用户直觉。
3. **红绿高亮预览与历史时间线**：
   - 抽象 `ActionCardPreview` 组件：提取选中列前 5 行样例，本地执行或通过轻量操作计算前后预览，呈现直观的对比；
   - 将底层 `core/text-transform` 等机器描述转换为本地化人类可读的动作摘要。
4. **模板保存与清洗体检报告**：
   - 保存方案：直接复用后端的 `POST /api/pipelines` 机制，将当前 Recipe 命名存储为清洗方案；
   - 成果报告：基于前后质量摘要与步骤统计，前端渲染轻量级、可视化良好的汇报模态框。

---

## Diff Against Proposal

- **变动性质**：纯增量（Additive Detail）。
  - 细化了具体卡片动作的映射规范与大白话描述；
  - 明确了高阶 GREL 表达式的折叠兜底机制；
  - 细化了清洗体检成果单的字段与呈现形态。
- **裁决**：Auto 模式下自批准（Self-approved），无裁决冲突。
